# 任务五 · 三节点副本集部署手册

节点：NoSQL1 `192.168.78.129`、NoSQL2 `192.168.78.130`、NoSQL3 `192.168.78.131`
统一端口：**27018**，数据目录 `/data/rs0`，日志 `/data/rs0.log`
副本集名称：`rs0`

> 与单机 27017 端口错开，三个环境可同时运行，答辩时能连续演示。

## 0. 前置检查（三台都做）

```bash
mongod --version | head -1        # 必须 8.0.x，三台一致
sudo mkdir -p /data/rs0
sudo chown -R $USER:$USER /data
```

若版本不一致，先统一安装再继续，否则副本集初始化会因版本差异失败。

## 1. 生成 keyfile（三台内容必须完全一致）

在 NoSQL1 上生成，然后复制到另外两台：

```bash
openssl rand -base64 756 | sudo tee /data/keyfile > /dev/null
sudo chmod 400 /data/keyfile
sudo chown $USER:$USER /data/keyfile
```

复制到 NoSQL2/NoSQL3：

```bash
scp /data/keyfile guohanming@192.168.78.130:/data/keyfile
scp /data/keyfile guohanming@192.168.78.131:/data/keyfile
```

在目标机上补权限：`sudo chmod 400 /data/keyfile`。

## 2. 三台分别启动（顺序无所谓）

```bash
mongod --replSet rs0 \
       --port 27018 \
       --dbpath /data/rs0 \
       --logpath /data/rs0.log \
       --bind_ip 0.0.0.0 \
       --keyFile /data/keyfile \
       --fork

pgrep -a mongod        # 确认进程在
```

## 3. 初始化副本集（只在 NoSQL1 上做）

```bash
mongosh --port 27018
```

```js
rs.initiate({
  _id: "rs0",
  members: [
    { _id: 0, host: "192.168.78.129:27018", priority: 2 },
    { _id: 1, host: "192.168.78.130:27018", priority: 1 },
    { _id: 2, host: "192.168.78.131:27018", priority: 1 }
  ]
})
```

等 10 秒左右：

```js
rs.status().members.map(m => ({ name: m.name, state: m.stateStr, health: m.health }))
```

期望：一台 `PRIMARY`、两台 `SECONDARY`，`health` 全为 1。

## 6. 验证复制与读取偏好

**主节点写入：**

```js
mongosh "mongodb://app_rw:App2026@192.168.78.129:27018/smartlib?authSource=smartlib&replicaSet=rs0"
db.books.insertOne({ isbn: "TEST-RS-001", title: "副本集验证", price: 1 })
```

**从节点读（默认不可读，必须指定读偏好）：**

```js
mongosh "mongodb://app_rw:App2026@192.168.78.130:27018/smartlib?authSource=smartlib&replicaSet=rs0&readPreference=secondary"
db.books.findOne({ isbn: "TEST-RS-001" })       // 能读到，说明复制成功
db.books.countDocuments()                        // 只读节点可查
```

**两种读偏好的区别：**

| 读偏好 | 行为 | 适用场景 |
|---|---|---|
| `primary`（默认） | 只读主节点 | 借阅登记后立刻查结果，要求强一致 |
| `secondaryPreferred` | 优先读从节点，无从节点才回主 | 馆藏浏览、统计报表，允许秒级延迟 |

```js
db.getMongo().setReadPref("secondaryPreferred")
db.books.countDocuments()
```

## 7. 故障转移演练（核心，必须记录时间）

**演练前记录：**

```js
rs.status().members.map(m => ({ name: m.name, state: m.str }))
```

**手动让主节点退位：**

```js
rs.stepDown(60)      // 60 秒内不参与选举
```

立即在另一台查看：

```js
rs.status().myState          // 1 = PRIMARY
rs.status().members.map(m => ({ name: m.name, state: m.str, electionDate: m.electionDate }))
```

记录：退位时间、新主节点 IP、选举耗时（`electionDate` 与操作时间的差，通常 5—10 秒）。

**写入影响：** 退位期间连原主节点的写会失败并返回 `NotWritablePrimary`，客户端需重试；读若走 secondaryPreferred 不受影响。

**原主节点回归：** 60 秒后自动重新加入，角色变为 `SECONDARY`（priority 为 2，不会立刻抢回主）。
