# 任务六 · 分片集群部署手册

拓扑（3 台足以跑通，端口全部错开）：

| 角色 | 主机 | 端口 | 数据目录 | 说明 |
|---|---|---|---|---|
| 配置服务器 cfgrs | NoSQL1 192.168.78.129 | 27019 | /data/cfg | 单节点副本集（CSRS） |
| 分片一 shard1 | NoSQL2 192.168.78.130 | 27020 | /data/shard1 | 单节点分片 |
| 分片二 shard2 | NoSQL3 192.168.78.131 | 27021 | /data/shard2 | 单节点分片 |
| 路由 mongos | NoSQL1 192.168.78.129 | 27022 | — | 应用统一入口 |

> 分片集群的"单节点分片"在教学中可用，但生产环境每个分片都应是副本集。文档里要写清这一简化。

## 0. 前置

```bash
# 三台都确认，且先停掉副本集实例，避免端口/内存冲突
pkill mongod || true
sudo mkdir -p /data/cfg /data/shard1 /data/shard2
sudo chown -R $USER:$USER /data
ls -l /data/keyfile        # 沿用任务五的 keyfile，三台一致
```

## 1. 启动配置服务器（NoSQL1）

```bash
mongod --configsvr --replSet cfgrs \
       --port 27019 --dbpath /data/cfg \
       --logpath /data/cfg.log --bind_ip 0.0.0.0 \
       --keyFile /data/keyfile --fork
```

初始化（NoSQL1）：

```bash
mongosh --port 27019
```

```js
rs.initiate({ _id: "cfgrs", members: [{ _id: 0, host: "192.168.78.129:27019" }] })
rs.status().myState      // 1 = PRIMARY
```

## 2. 启动两个分片

**NoSQL2：**

```bash
mongod --shardsvr --port 27020 --dbpath /data/shard1 \
       --logpath /data/shard1.log --bind_ip 0.0.0.0 \
       --keyFile /data/keyfile --fork
```

**NoSQL3：**

```bash
mongod --shardsvr --port 27021 --dbpath /data/shard2 \
       --logpath /data/shard2.log --bind_ip 0.0.0.0 \
       --keyFile /data/keyfile --fork
```

## 3. 启动 mongos（NoSQL1）

```bash
mongos --configdb cfgrs/192.168.78.129:27019 \
       --port 27022 --bind_ip 0.0.0.0 \
       --logpath /data/mongos.log --keyFile /data/keyfile --fork
```

## 4. 建管理员并加入分片

keyfile 已启用认证，集群中还没有任何用户，此时可通过本地例外建第一个用户：

```bash
mongosh --port 27022
```

```js
use admin
db.createUser({ user: "root", pwd: "Root2026", roles: ["root"] })
db.auth("root", "Root2026")

sh.addShard("192.168.78.130:27020")
sh.addShard("192.168.78.131:27021")
sh.status()
```

期望：`shards` 下有两个分片，`balanced: true`。

## 5. 建业务账号并启用分片

```js
use smartlib
db.createUser({ user: "app_rw", pwd: "App2026", roles: [{ role: "readWrite", db: "smartlib" }] })
db.createUser({ user: "app_ro", pwd: "Ro2026",  roles: [{ role: "read", db: "smartlib" }] })

sh.enableSharding("smartlib")
```

**关键顺序：先建索引，再分片。**

```js
use smartlib
db.borrow_logs.createIndex({ reader_card: 1, borrow_date: 1 })
sh.shardCollection("smartlib.borrow_logs", { reader_card: 1, borrow_date: 1 })
```

若报 `could not find index` 说明索引没建或字段顺序不一致，必须与分片键前缀完全一致。

从有数据文件的那台机器（NoSQL1）执行，走 mongos：

```bash
export MONGO_URI="mongodb://app_rw:App2026@192.168.78.129:27022/smartlib?authSource=smartlib"
export MONGO_DB="smartlib"
export MONGO_USERNAME="app_rw"

```

> 只导入即��，不要 --reset，避免把已建好的分片配置清掉（reset 只删库，不影响分片元数据，但导入前确认集合已分片）。

## 7. 验证数据分布（这一步决定任务六成败）

```js
sh.status()
db.borrow_logs.getShardDistribution()
```

**如果 3000 条全落在一个分片**（大概率，因为 3000 条约 600KB，远小于 128MB 的 chunk 上限，均衡器不会自动切分），需要手动切分并迁移，这本身就是一次很好的演示：

```js
// 取一个中间值作为切分点
const mid = db.borrow_logs.find().sort({ reader_card: 1, borrow_date: 1 }).skip(1500).limit(1).next()
sh.splitAt("smartlib.borrow_logs", { reader_card: mid.reader_card, borrow_date: mid.borrow_date })

// 把其中一个 chunk 迁到另一个分片
sh.status()                       // 先看 chunk 落在哪个分片
sh.moveChunk("smartlib.borrow_logs", { reader_card: mid.reader_card, borrow_date: mid.borrow_date }, "shard02")
```

再查：

```js
db.borrow_logs.getShardDistribution()
```

应看到两个分片各约 1500 条。

📷 截图 T6-05（必须能看到两个分片的文档数）。

## 8. 定向查询 vs 跨分片查询

**定向（带完整分片键）：**

```js
db.borrow_logs.find({ reader_card: "R20240001", borrow_date: { $gte: ISODate("2024-01-01") } })
  .explain("executionStats").queryPlanner.winningPlan
```

期望：`SINGLE_SHARD`，只访问一个分片。

**跨分片（不带分片键）：**

```js
db.borrow_logs.find({ status: "逾期" }).explain("executionStats").queryPlanner.winningPlan
```

期望：`SHARD_MERGE`，两个分片都参与。

📷 截图 T6-06、T6-07。

## 9. 分片键论证（写进文档，不少于 500 字）

**选择 `{reader_card: 1, borrow_date: 1}` 的依据：**

1. **基数**：30 位读者 × 三年时间，实际组合约 3000 种，远高于单字段 `{status: 1}`（3 种）；
2. **写分布**：每个读者约 100 条流水，按读者切 chunk 后两片各约一半，不会出现单点写入；
3. **查询支持**：平台高频查询是"某读者某段时间的借阅"，带分片键前缀可直接定向。

**备选方案与不选的理由：**

| 备选 | 优点 | 不选原因 |
|---|---|---|
| `{borrow_date: 1}` | 范围查询友好 | 单调递增，新写入全落在最后一个 chunk，形成写热点 |
| `{book_isbn: "hashed"}` | 分布均匀 | 只支持等值查询，无法按读者+时间范围检索 |
| `{status: 1}` | 简单 | 基数仅 3，两片数据严重倾斜 |
| `{reader_card: "hashed"}` | 均匀 | 支持等值但不支持时间范围，读者区间查询要全分片广播 |

## 10. 收尾

```js
sh.status()
db.borrow_logs.getShardDistribution()
db.borrow_logs.countDocuments()     // 仍应为 3000
```

三台执行 `pkill mongos; pkill mongod`，再回到单机/副本集环境时重新启动即可。
